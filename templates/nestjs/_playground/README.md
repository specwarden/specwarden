# nestjs playground

`repository/` pretends to be a NestJS + TypeORM service — `ledger-api`: a module with a
controller, a service, an entity and a repository, behind a compose stack — the kind of
backend the template is for, entity included so the ORM barrier is proved against a real
one rather than an empty `repositories/` folder.

`.specwarden/` there is exactly what `init --template nestjs` writes today: generated by
`node scripts/playgrounds.mjs --write nestjs`, never edited by hand. `migrations-backwards-compatible`
and `env-pairing` ship as `.example` — a migration policy and a compose reconciliation
each need a fact only a real repository has — and are proved separately, by the
template's own unit suite importing and constructing them.

## What each defect proves

| Check | Plants | Says |
| --- | --- | --- |
| `nestjs-db-access` | a service that builds its own query instead of asking the repository | `repository/src/modules/invoices/invoices.service.ts` |
| `secret-scan` | a committed `.env` with a real access key in it | `.env` |
| `unit` | a total that stopped rounding each line — the service's own test catches it | `npm test` |

## Regenerating

After changing the template: `pnpm --filter @specwarden/template-nestjs build`, then
`node scripts/playgrounds.mjs --write nestjs` — review the `.specwarden/` diff before
committing it.
