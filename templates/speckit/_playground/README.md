# speckit playground

`repository/` pretends to be a passwordless sign-in service — `doorman` — specified with
Spec Kit: a constitution, two features each with their own `spec.md` and `tasks.md`, the
code, and its tests. Two features that both number their requirements from `FR-001` are
deliberate: Spec Kit numbers per feature.

`.specwarden/` there is exactly what `init --template speckit` writes today: generated by
`node scripts/playgrounds.mjs --write speckit`, never edited by hand.

## What each defect proves

| Check | Plants | Says |
| --- | --- | --- |
| `doc-paths` | the README pointing at a test file that was never written | `test/sessions.test.ts` |
| `secret-scan` | a mail provider key committed beside the link issuer | `src/mailer.ts` |
| `unit` | a link that no longer expires — FR-002 broken, and the suite says so | `npm test` |

Beside the checks, `sync-invariants` over this tree is proved directly (not through
`provePlayground`, since reconciling a spec source is not a check): every requirement of
every feature is read — two `FR-001`s stay two — and the command says it FOUND NOTHING —
never "in sync" — when there is no specs directory.

## Regenerating

After changing the template: `pnpm --filter @specwarden/template-speckit build`, then
`node scripts/playgrounds.mjs --write speckit` — review the `.specwarden/` diff before
committing it.
