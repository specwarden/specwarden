# ops playground

`repository/` pretends to be an infrastructure repository — `harbor-infra`: a compose
stack behind nginx, deploy and backup scripts, runbooks, a deploy workflow — the kind of
repository whose product is the OPERATION of something else, and whose failures are
found in production, at the worst hour.

`.specwarden/` there is exactly what `init --template ops` writes today: generated by
`node scripts/playgrounds.mjs --write ops`, never edited by hand. `env-pairing`,
`proxy-upstreams` and `ci-coverage` ship as `.example` — each needs a fact about this
deployment only a real repository has — and are proved separately, by the template's
own unit suite importing and constructing them.

## What each defect proves

| Check | Plants | Says |
| --- | --- | --- |
| `secret-scan` | an access key hard-coded into the backup script "just for tonight" | `repository/scripts/backup.sh` |
| `shell-scope` | `local` in the main body of a script, outside any function | `repository/scripts/backup.sh` |
| `doc-paths` | a runbook naming a restore script nobody wrote | `scripts/restore.sh` |

## Regenerating

After changing the template: `pnpm --filter @specwarden/template-ops build`, then
`node scripts/playgrounds.mjs --write ops` — review the `.specwarden/` diff before
committing it.
